# Mike Hamanaka · Hamanaka Software Factory

**Mike Hamanaka** · San Francisco · [sjultra](https://sjultra.com) · [edgerecord.com](https://edgerecord.com)

I build local-first tools for capturing intent, coordinating AI coding sessions,
verifying results, and learning from failures. The Hamanaka Software Factory
brings these projects together around explicit responsibilities and human control.

> Less repeated context. More accepted work. Visible failures.

## Start here

- **Capture browser intent:** [Panther Intent Capture](https://github.com/hamanakam1/panther-intent-capture)
  turns selected context into reviewable proposals and opt-in ticket delivery.
- **Coordinate agent sessions:** [TaskRivet](https://github.com/hamanakam1/taskrivet)
  focuses on bounded context, ownership, and evidence trails for AI CLI work.
- **Understand the ticket format:** [FluxRecord](https://github.com/hamanakam1/fluxrecord)
  describes a standard for evidence-driven coordination.
- **Browse the public work:** [all public repositories](https://github.com/hamanakam1?tab=repositories)
  and the [project atlas source and local preview guide](https://github.com/hamanakam1/hamanakam1.github.io).

## Principles

- **Local first.** Prefer local inference, local ledgers, and local Git. Make
  external services, data transfers, and costs explicit choices.
- **Visible failures.** A failure with a recorded reason is worth more than a
  success nobody can check.
- **Bounded authority.** Every component states what it may do, and — more
  importantly — what it may not.
- **Evidence over claims.** A diff is not an intent. A finished session is not
  accepted work. Declared usage is not measured billing.
- **Synthetics in public.** Use synthetic fixtures, screenshots, and examples
  that do not identify real systems or deployments.

## Explore and contribute

- For corrections to this profile or its links, see the
  [profile contribution guide](CONTRIBUTING.md).
- Start with the relevant project's README for supported workflows and
  installation instructions. Consult its releases before choosing a version.
- Report bugs and suggest improvements in that project's issue tracker, following
  its contribution guidelines where provided. Include the expected result,
  actual result, and a minimal reproduction using synthetic data.
- Keep credentials, private logs, and identifying screenshots out of public
  reports. Reproducible evidence helps maintainers assess the problem.
